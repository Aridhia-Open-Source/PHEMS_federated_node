# Prerequisites

> **This page is for chart 1.x.** For 2.x, see [Prerequisites](./Prerequisites).

Before deploying the Federated Node, make sure the following are in place.


## Required tools

| Tool | Purpose | Install guide |
|---|---|---|
| `kubectl` | Interact with your Kubernetes cluster | [docs.kubernetes.io](https://kubernetes.io/docs/tasks/tools/) |
| `helm` (v3+) | Deploy the FN chart | [helm.sh/docs/intro/install](https://helm.sh/docs/intro/install/) |
| `jq` | Parse API responses in shell examples | [stedolan.github.io/jq](https://stedolan.github.io/jq/download/) |

Example `values.yaml` files for each platform are provided throughout the deploy guides in this documentation.


## Required infrastructure

### Kubernetes cluster

Any CNCF-conformant Kubernetes cluster works. Tested platforms:

- Azure Kubernetes Service (AKS)
- AWS Elastic Kubernetes Service (EKS)
- Google Kubernetes Engine (GKE)
- On-premises (RKE2)

Other CNCF-conformant distributions should work but have not been formally tested.

Minimum recommended node specs: **4 vCPU / 8 GB RAM**. Analytics task pods spin up alongside the base FN pods, so size your cluster for your expected concurrent workload.

### PostgreSQL database

The FN needs a PostgreSQL instance for its own internal metadata (users, datasets, task records, audit logs). This is **not** the database containing your research data.

- PostgreSQL 12+ works (managed or self-hosted)
- The FN creates its own schema on first startup via Alembic migrations
- You need the hostname, port, database name, username, and password ready before deploying

### Persistent storage

The FN needs a persistent volume to temporarily hold task results between job completion and the researcher retrieving them. Four storage backends are supported:

- **Azure File Share** - for AKS deployments
- **AWS EFS** - for EKS deployments
- **Google Cloud Storage** - For GKE deployments
- **NFS** - cloud-agnostic, on-prem friendly
- **Local host path** - single-node / development only

See the platform-specific deploy guide for configuration details.

## Critical: pre-install Gateway API and Traefik CRDs

If you plan to use Traefik as the ingress controller (`traefik.enabled: true`, recommended for production), you **must** install two sets of Kubernetes CRDs before running `helm install`. The chart will fail at install time with a clear error message if these are missing.

```sh
# 1. Gateway API CRDs
kubectl apply --server-side -f \
  "https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.4.0/standard-install.yaml"

# 2. Traefik CRDs
kubectl apply --server-side -f \
  "https://raw.githubusercontent.com/traefik/traefik/v3.6/docs/content/reference/dynamic-configuration/kubernetes-crd-definition-v1.yml"
```

This is a one-time step per cluster. If you are deploying without Traefik (`traefik.enabled: false`), you can skip it.

## Notes on secrets

The FN values file supports referencing pre-created Kubernetes secrets rather than embedding credentials as plain text. This is strongly recommended for production.

A few characters cause problems in shell `--from-literal` commands: `"` must be escaped as `\"`, and `%` requires special handling. When in doubt, use the YAML manifest approach and pre-encode values with `echo -n "yourvalue" | base64`.

If you plan to deploy into a **non-default namespace**, create it before creating any secrets - secrets created in the wrong namespace won't be visible to the FN pods:

```sh
kubectl create namespace <your-namespace>
```
