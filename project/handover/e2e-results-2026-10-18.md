## Bugs spotted (not fixed)

1. `dagster/app/definitions/sensors/task/run_status.py:44-49` with `dagster/fncli/cmds/verify.py:225`: task finished SUCCESS with `started_at` None. started_at is only written when the sensor sees the run in STARTED; a short run that goes STARTED to SUCCESS between ticks never gets it. Suspected cause, not confirmed. Fails happy path `test_verify_repo`.
2. S6: `FncliBackendAPI` logs in as the dagster System user (`dagster/fncli/cmds/common.py:136-150`); the revoke endpoints need admin (`webserver/app/helpers/revoke.py:13`, `projects_api.py:227,326`). So fncli `link-set --revoked` always returns 403. S6, S5b and S10 cannot run until the test uses an admin token.
3. `dagster/fncli/tests/e2e/test_failure_paths.py:461-463` (S11): asserts "Ingest failed" in `tick["error"]["message"]`, but that field only holds the `SensorExecutionError ... evaluation_fn` wrapper. The inner text is probably in the error cause or stack. The behaviour (7 FAILURE ticks) is right.
4. `dagster/fncli/tests/e2e/conftest.py:104`: `ProjectConfig().namespace` does not exist (field is on `GiteaConfig`). Fixed, see below.
5. `conftest.py` / `test_failure_paths.py:74`: the autouse `fast_sensors` fixture builds `ProjectConfig()` before the `fncli` fixture runs `load_dotenv`, so `pytest dagster --e2e failure` alone fails with empty config. It only works after the success suite in the same process, or with `.dev.env` exported. I exported it.
6. `keycloak-realm-init` pod is in CrashLoopBackOff after deploy: realm migration 2 (client secret rotation policy) gets 400 "proposed client profile contains the executor, which does not have valid provider". The e2e suites still ran.
7. Flaky: right after the sensor-interval code-server restart, `test_start_sensor[task_queued_sensor]` once got SensorNotFoundError (location not reloaded yet). Passed on the rerun.
