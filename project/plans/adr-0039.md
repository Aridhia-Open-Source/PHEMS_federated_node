# Plan: ADR 0039 Fednode Shared Package (fednode/1, #765)

Status: not started. Write `project/decisions/0039-fednode-shared-package.md` (MADR, present tense) and add its rows to
`project/decisions/README.md` and `docs/README.md`. Source: the agreed design (below).

Decision to record:
- One shared package `fednode` (today's `nexus/client`), installed by nexus-api, Dagster, the operator and fncli.
- What goes in: transport (`http.py`: HttpClient, RetryAdapter, ClientError, ClientTimeout), clients (`clients/nexus`,
  `keycloak` (login, admin, keys), `dagster`, `kubernetes` (client with in_cluster|kubeconfig, MountedSecret, names),
  `git` (provider, github, gitea, uri)), shared settings (`settings.py`), and fncli as `fednode/cli` behind the `cli` extra.
- What never goes in: business rules, nexus-api models/DTOs, anything that decides (ADR 0021).
- Settings convention: every settings class on `fednode.settings.EnvSettings`; shared classes have every field optional;
  a service makes a field required by redeclaring it with a plain type; env name = settings path in capitals (env_prefix,
  no aliases); chart values carry the owner (`nexus.database.name` -> nexus-api `DATABASE_NAME`).
  `services.*` = systems a service calls; `database` = owned. Exceptions: Dagster chart `dagster.postgresql.*`, Keycloak `KC_DB_*`.
- Supersedes ADR 0038 (one outbound client layer): the shared HttpClient is that layer for every service. When this ADR
  lands, delete 0038 from the authorization stack and repoint its references here.
Alternatives: no shared code (naming convention only); settings in each service only; aliases per field.
