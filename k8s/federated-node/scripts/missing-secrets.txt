{{- if not .Values.db.createPasswordSecrets }}
db.createPasswordSecrets is false, so the chart creates no password Secrets - create
them with whatever owns your secrets (External Secrets, SealedSecrets, Vault). The
chart never needs their value at render time; it reads them through secretKeyRef at
runtime, which is also why this works under ArgoCD.
{{- else if .Values.db.manageRolesAndDatabases }}
Everything else is handled for you. The per-service database passwords
(backend, keycloak and dagster roles, and any dataset roles) are generated by
this chart on first install, reused on every upgrade, and copied into the
namespaces that need them - do not create those by hand.

To see the generated ones:

  kubectl get secret -n {{ .Release.Namespace }} -l federatednode.com/generated-password=true
{{- else }}
db.manageRolesAndDatabases is false, so you also need one secret per database role.
Install again once the above is fixed and the chart will list them, with the DDL to
create the roles themselves.
{{- end }}
